# 運用手順（当日の準備・トラブル対応）

設計の背景は [ARCHITECTURE.md](ARCHITECTURE.md)、概要は [README](../README.md) を参照。

## 機材

| 役割 | 台数 | 必要なもの |
|---|---|---|
| ホスト（レジ1） | ノートPC 1台 | Python 3.10 以上、または `MistyPOS.exe` |
| スタンバイ（レジ2） | ノートPC 1台 | 同上 |
| バーテン | iPad またはノートPC 1台 | ブラウザのみ |

ルーターやサーバーは使わない。ホスト機の Windows モバイルホットスポットに全端末をつなぐ。

## セットアップ（初回のみ）

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS / Linux: source .venv/bin/activate
pip install -r requirements.txt
```

手元で試すだけなら `python run.py` で起動し、`http://127.0.0.1:5000/` を開く。

## 当日の起動

### ホスト（レジ1）

1. モバイルホットスポットをオンにする
2. `scripts/start_host.bat` をダブルクリック
3. 接続画面（`/`）の QR をバーテン端末・スタンバイ機で読み取る

### スタンバイ（レジ2）

1. ホットスポットの SSID とパスワードをホストと同じにしておく（昇格時に各端末が自動で乗り換えるため）
2. `scripts/start_standby.bat` の `MISTY_PEER_URL` がホストのアドレスと一致しているか確認する
3. `scripts/start_standby.bat` をダブルクリック。以後は画面を触らない

スタンバイはホストと一度も同期できていない間は昇格しない（空のデータでホストになるのを防ぐため）。
ホストより先にスタンバイを起動しても問題ない。

## 設定（環境変数）

すべて `misty/config.py` の `Settings` に定義がある。不正な値を渡すと起動時にエラーで止まる。

| 環境変数 | 意味 | 既定値 |
|---|---|---|
| `MISTY_ROLE` | `host` または `standby` | `host` |
| `MISTY_DEVICE_NAME` | 画面・操作ログに出る端末名 | `レジ1` |
| `MISTY_PEER_URL` | standby が監視する host の URL | `http://192.168.137.1:5000` |
| `MISTY_PORT` | 待受ポート | `5000` |
| `MISTY_MIRROR_INTERVAL_SEC` | 複製の周期（秒） | `2.5` |
| `MISTY_FAILOVER_THRESHOLD_SEC` | 何秒応答がなければ昇格するか（周期の2倍以上） | `10` |
| `MISTY_CLUSTER_TOKEN` | host/standby 間の共有トークン（任意） | 空 |
| `MISTY_MENU_SHEET_CSV_URL` | メニュー取込元のスプレッドシート | 空 |
| `MISTY_ADVERTISE_HOST` | QR に載せるアドレスを固定する | 空（自動選択） |

## メニューの準備（Google スプレッドシート）

1. 部の Google アカウントでスプレッドシートを作り、「リンクを知っている全員（閲覧者）」で共有する
2. 1行目に見出し、2行目以降に商品を入れる（列名は日本語・英語どちらでもよい）

   ```
   商品名, カテゴリー, 価格, 在庫数
   ジンジャーエール, ソフトドリンク, 300, 40
   ```

3. 開店前に管理画面の「読み込む」にブラウザの URL をそのまま貼る

- 既存の商品は名前で照合し、価格とカテゴリーを上書きする
- 在庫数は、まだ売れていない商品だけ上書きする（営業中に取込し直しても在庫が巻き戻らない）
- 価格が読めない行などは読み飛ばし、行番号と理由を画面に出す
- 共有設定が非公開のままだと「CSV ではなく Web ページが返ってきました」と表示される

カテゴリー列はレジ画面の枠になる（例: 「コーヒー（ホット）」「コーヒー（コールド）」）。
年度をまたぐときは前年のタブを複製して使う。

## 営業後のバックアップ・照合

管理画面から3種類の CSV を書き出せる（Excel でそのまま開けるよう BOM 付き UTF-8）。

- 注文明細 `/api/export/orders.csv`
- 売上サマリー `/api/export/summary.csv`
- 操作ログ `/api/export/log.csv`

フェイルオーバーが起きた日は、旧ホストを起動して（自動でフェンスされ読み取り専用になる）
その操作ログ CSV も書き出し、新ホストのものと突き合わせる。
旧ホストが最後に複製されてから停止するまでの数秒間の会計は、旧ホストの DB にだけ残っている。

## つながらないとき

1. 端末が本当にホスト機のホットスポットに繋がっているか（大学の Wi-Fi 等に自動接続していないか）
2. 接続画面の「QR で繋がらないとき」に出ている別のアドレスを試す
   （ホスト機が上流の Wi-Fi とホットスポットの両方に繋がっていると、アドレスが2つある）
3. Windows Defender ファイアウォール: 初回起動時の確認ダイアログで「プライベート」「パブリック」
   の両方を許可したか。ホットスポット側はパブリック扱いになることが多い。
   許可し忘れたら「Windows セキュリティ → ファイアウォールとネットワーク保護 →
   アプリをファイアウォール経由で許可する」から `python.exe` または `MistyPOS.exe` を追加する
4. ホスト機自身のブラウザで `http://<ホスト機のIP>:5000/` が開けるか確認し、
   ホスト側の問題か端末側の問題かを切り分ける

## 実機検証チェックリスト（本番前に必ず確認）

自動テストと障害訓練スクリプトは Linux / Windows の CI で通しているが、
以下はホットスポットや OS の設定に依存するため実機でしか確認できない。

- [ ] ホットスポットのゲートウェイが `192.168.137.1` か（`ipconfig`。違えば `start_standby.bat` を修正）
- [ ] ホストとスタンバイのホットスポットが同じ SSID・パスワードか
- [ ] ホスト機の電源を切ったとき、各端末がスタンバイの電波に自動で再接続するか、何秒かかるか
- [ ] スタンバイ昇格時のホットスポット自動起動（`misty/network.py`）が動くか。
      失敗すると操作ログに `hotspot_start` が `ok: false` で残るので、手動でオンにする
- [ ] 上流のネット接続がない状態で、Windows がホットスポットを起動できるか
      （自動起動は `NoConnectionProfile` で失敗する可能性がある）
- [ ] iPad の Safari で QR 読み取り → 「ホーム画面に追加」まで通るか
- [ ] スプレッドシートの CSV エクスポート URL が未ログインのブラウザで取得できるか

## Windows 用の実行ファイル（.exe）

Windows 上で次を実行すると `dist\MistyPOS\` 一式ができる。Python のインストールは不要になる。

```bat
pip install -r requirements.txt pyinstaller
pyinstaller scripts\misty.spec
```

`start_host.bat` / `start_standby.bat` は exe があればそちらを、なければ `python run.py` を使う。
